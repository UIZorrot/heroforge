# Hero Forge 产品报告

## 1. 产品一句话定义

Hero Forge 是一个以“图片锻造英雄”为入口、以“战术对战”为验证、以“Dust / Relics 经济”为驱动的生成式英雄竞技游戏。

它不是单纯的 AI 角色生成器，也不是传统卡牌展示页，而是一个把生成、收藏、训练、竞技和经济系统串成闭环的 live game 原型。

## 2. 产品本质

从产品经理视角看，Hero Forge 的核心不是“生成一个角色”，而是“把一个角色变成可被持续使用、验证、收藏和对战的游戏资产”。

产品的价值链是：

1. 用户上传图片
2. LLM 负责角色概念、名字、描述、模板和技能结构
3. 规则引擎负责最终数值和战斗可控性
4. 角色进入 Vault 成为长期资产
5. 用户在 Train 中试验阵容
6. 用户进入 PvP / Arena 竞争
7. Dust 和 Relics 作为消耗与成长资源，维持循环

这意味着 Hero Forge 的定位更接近“生成式英雄竞技平台”，而不是“AI 作图工具”。

## 3. 目标用户

从当前功能结构推断，产品主要服务四类用户：

1. 角色创作者
   - 喜欢把图片、OC、二创素材转换成游戏角色的人
   - 他们关心“生成结果是否像自己的角色”

2. 策略玩家
   - 关注 BP、模板、技能组合、阵容克制
   - 他们关心“这个英雄怎么配队、怎么打赢”

3. 收藏玩家
   - 关注 Vault、稀有度、材料 infusion、历史记录
   - 他们关心“我拥有什么、这些资产有什么价值”

4. 竞技玩家
   - 关注 PvP 队列、BP 匹配窗口、Dust stake
   - 他们关心“我能不能稳定赢、赢了有什么收益”

## 4. 核心使用场景

### 4.1 生成场景

用户上传一张图片，希望立刻得到一个可战斗的英雄卡。

### 4.2 验证场景

用户不满足于“生成得像”，还要看这个英雄能不能打，因此需要 Train / 沙盒战斗。

### 4.3 竞技场景

用户希望把英雄放进正式 PvP 环境，在有限 BP 窗口内进行匹配，并用 Dust 作为竞技成本。

### 4.4 收集和经营场景

用户会持续积累英雄、材料、战斗记录和经济流水，形成“我自己的英雄档案库”。

## 5. 产品主循环

当前产品的主循环非常明确：

1. 登录
2. 上传图片 Forge
3. 生成英雄
4. 存入 Vault
5. 在 Train 中测试
6. 进入 PvP / Arena
7. 消耗 Dust、获得或使用材料
8. 进入下一轮 Forge

这是一个典型的“创造 -> 验证 -> 竞争 -> 消耗 -> 再创造”的循环。

## 6. 功能模块拆解

### 6.1 账号和身份

- 使用邮箱验证码登录
- 通过 session token 保持登录状态
- 有清晰的会话、退出和用户状态检查

这说明产品希望降低注册门槛，让用户尽快进入核心玩法。

### 6.2 Forge：英雄锻造

- 支持图片输入
- 后端先识图，再生成结构化角色
- 最终数值不是 AI 直接生成，而是规则引擎决定
- 可注入材料，影响英雄风格和属性倾向

这是整个产品最独特的能力，也是最强的首发卖点。

### 6.3 Vault / Barracks：英雄仓库

- 展示已经锻造的英雄
- 支持搜索、排序、稀有度筛选
- 支持查看技能、属性、材料 infusion
- 支持将英雄派往训练或对战

这部分承担“资产沉淀”和“长期留存”的作用。

### 6.4 Train：沙盒对战

- 支持 1v1 和 3v3
- 主要用于试验技能、阵容和站位
- 不涉及正式竞技压力

这是用户理解系统、调试阵容、降低 PvP 挫败感的关键缓冲区。

### 6.5 Duel / Arena：正式 PvP

- 支持最多 4 个英雄组队
- 有 BP 匹配窗口限制
- 进入队列需要 Dust 成本
- 支持等待、取消和过期返还

这部分把产品从“生成玩具”抬升为“可持续竞技游戏”。

### 6.6 Chronicle / PvE

- 有主题塔式 PvE 框架
- 已经有 run、party、stage 等数据结构
- 但内容深度仍偏早期

这更像是未来内容池和运营扩展位，而不是当前主战场。

### 6.7 经济系统

- 主货币是 Dust
- 辅助资源是 Relics
- Dust 用于 Forge、Repair、PvE、PvP 进入和 stake
- 资源变化有交易流水记录

这说明产品已经具备 live game 的经济骨架。

## 7. 产品差异化

Hero Forge 的差异化不在“用了 AI”，而在于：

1. AI 只负责结构，不负责最终数值
2. 角色不是一次性结果，而是长期资产
3. 战斗不是纯展示，而是可验证、可复盘、可匹配
4. 经济系统真实存在消耗和约束

这让它比一般的 AI 角色生成器更像一个正式游戏服务。

## 8. 当前产品阶段判断

从代码和功能完整度看，这是一个已经有完整垂直切片的 Alpha / Early Beta 产品。

已经具备的能力：

- 登录
- Forge
- Vault
- Train
- PvP
- 经济
- 记录系统

还缺的能力：

- 更完整的 PvE 内容
- 更强的成长线
- 更完善的新手引导
- 更稳定的内容产出机制

## 9. Landing Page 问题总结

下面是目前 landing page 最需要优先改造的问题。

### 9.1 核心问题一：价值主张被风格淹没

当前 landing page 很努力地在营造“黑金、终端、科幻、仪式感”的氛围，但用户第一眼很难迅速回答三个问题：

- 这是什么产品
- 我为什么要点进去
- 我现在应该做什么

页面用了大量系统化术语和装饰性文案，例如：

- `SYSTEM_STABLE`
- `INITIATING_SEQUENCE`
- `NEXUS`
- `INTEL`
- `ARCHIVES`
- `MODULE_LOADED`
- `SCAN_COMPLETED`

这些元素强化了世界观，但削弱了理解速度。

### 9.2 核心问题二：主 CTA 不够明确

当前 landing page 同时在做很多事：

- 顶部按钮
- Hero 主 CTA
- 训练 CTA
- 底部再次 CTA
- 导航栏还有多个入口词

对新用户来说，这会造成“到底先做 Forge、还是先看 Train、还是先登录”的困惑。

landing page 最重要的职责应该是把用户送进核心路径，而不是展示所有氛围和模块。

### 9.3 核心问题三：信息架构过长，首屏后拖沓

页面用了多个大段落和视觉分区：

- Hero
- 三段 story line
- System protocols
- Exit portal
- Footer

这会造成明显的滚动负担。

对 landing page 来说，用户通常只想快速确认：

1. 这是什么
2. 怎么开始
3. 值不值得开始

现在的结构把“信息证明”放得太后面。

### 9.4 核心问题四：品牌视觉风格过饱和，接近模板化 AI 科幻审美

当前页面大量使用：

- 深色背景
- 金色发光
- 扫描线
- 颗粒纹理
- 终端式字样
- 科幻 HUD 元素

这套语言有气氛，但问题是它非常接近常见的“AI 生成科幻 landing page”模板。

如果没有更强的独特视觉母题，页面会显得“高级但不记忆深刻”。

### 9.5 核心问题五：产品能力没有被具象化

landing page 讲了很多“原则”和“感觉”，但没有强有力地展示：

- 真实 Forge 流程长什么样
- 英雄生成结果长什么样
- 战斗事件长什么样
- Dust 和 Relics 如何影响玩法

也就是说，页面表达的是“世界观”，而不是“产品证据”。

### 9.6 核心问题六：导航结构存在理解和交互问题

代码里有几个明显信号：

- 顶部导航使用了 `#nexus / #intel / #archives`
- 但页面没有对应的锚点内容
- 左右两处 CTA 都会导向 Forge 或登录
- 视觉上的导航和真实可达内容并不匹配

这会破坏用户对页面的信任感。

### 9.7 核心问题七：移动端可读性和节奏风险较高

页面包含很多大字号标题、超大留白、双栏叙事块和悬浮英雄卡。

这些设计在桌面端可能有仪式感，但在移动端很容易出现：

- 首屏信息被压缩
- 滚动距离过长
- 重点内容被装饰元素稀释

### 9.8 核心问题八：页面缺少“下一步”的明确教学

landing page 应该帮助新用户完成第一步心智转换：

- 先理解你是做什么的
- 再知道你要上传什么
- 再知道生成后会发生什么

当前页面更像品牌展示，而不是带用户进入玩法的 onboarding 页面。

## 10. 改造优先级建议

### P0

1. 重做首屏价值主张
   - 一句话讲清楚 Hero Forge 到底是什么
   - 把 Forge 作为唯一主 CTA

2. 收敛导航和 CTA
   - 取消重复入口
   - 让用户只看到一个最明确的开始动作

3. 补强产品证据
   - 让 landing page 直接展示 Forge / Hero / Battle 的真实结果

### P1

4. 降低 jargon 密度
   - 减少系统术语堆砌
   - 用更直接的产品语言替代部分仪式化文案

5. 优化信息层级
   - 把“Forge -> Train -> PvP -> Economy”改成更顺的故事线

### P2

6. 调整视觉母题
   - 保留黑金调性，但减少模板化科幻元素
   - 增加更具 Hero Forge 识别度的资产展示方式

7. 重新组织移动端首屏
   - 让关键 CTA、价值主张、样例英雄更集中

## 11. 结论

Hero Forge 这个产品的核心很强，landing page 目前最大的问题不是“做得不够酷”，而是“酷感压过了产品说明力”。

如果目标是拉新和转化，landing page 应该优先完成三件事：

1. 让新用户 3 秒内知道这是什么
2. 让新用户 5 秒内知道怎么开始
3. 让新用户 10 秒内相信这不是普通 AI 生成页，而是真正可玩的游戏
