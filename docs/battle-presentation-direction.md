# 战斗展示改进方向

评估依据：用户提供的战斗截图、项目 `.impeccable.md` 和 `ArenaBattleScene.tsx`。这是展示层设计评估，尚未逐场验证实时战斗、错误恢复和所有设备。胜利与失败效果按用户反馈保留。

## 判断

整体具有明确的暗黑仪式风格，不是通用 AI 模板。但重复框线、过多并列信息区和大面积低对比文字，削弱了品牌要求的“战斗是主角”。反模式检查：风格辨识通过，信息容器过密未通过。

已有基础值得保留：卡面美术与金属色统一；阵型、血量、行动顺序可供复盘；已有投射物、命中与结果演出。最大机会是统一空间和事件节奏，而非继续堆叠粒子。

## 优先问题

| 优先级 | 问题与影响 | 改进 | 对应设计动作 |
| --- | --- | --- | --- |
| P1 | 两侧指挥官、重复头像与底部多处战报压缩战场；视线在多个区域来回移动 | 顶部压缩为双方身份、存活数和回合；战场成为主体；底部保留行动顺序，完整日志按需展开 | /arrange、/distill |
| P1 | 攻击者、受击者、结果缺少统一的视觉叙事 | 将抬升、前移、投射物抵达、受击、扣血和复位绑定到同一事件时间轴 | /animate |
| P1 | 7–10px 等微小字号承担了名字、状态、血量和战报信息 | 常驻只保留名字、血量、关键状态；增加信息字号；属性与解释通过悬停、键盘聚焦或点击查看 | /typeset、/clarify |
| P2 | 空槽采用接近实体卡牌的重框线，战场缺少实体与地面区分 | 空槽改为石面上的浅刻痕；实体卡有薄厚度、统一光照、接触阴影 | /quieter、/bolder |
| P2 | 多张敌方卡背难以凭图像区分单位 | 检查素材映射；已公开单位使用角色图，没有图则使用不同职业徽记；隐藏信息继续遵守游戏规则 | /clarify |

## 推荐空间方案：斜俯视仪式牌桌

- 第一版保留现有左右对阵和槽位语义，用浅透视建立一张连续的牌桌；不同时改变规则和空间阅读方式。
- 桌面使用磨损石材和旧金属，阵位刻在桌面上。背景建筑退到远景，减少与卡面的高频细节竞争。
- 竖版卡牌继续使用统一的 2:3 原始比例，整齐排列。透视投影允许视觉缩短，但不改变卡片源尺寸比例。常态没有随机歪斜。
- 所有牌共享同一个相机与光源；待机时贴近桌面，有薄侧边与接触阴影。当前行动牌抬升、略微朝视线转正并前移，受击牌短促后退。
- 阴影距离随抬升变化，投射物和落点跟随投影后的卡牌位置；血量和状态保持清晰，必要时以屏幕空间标签呈现。
- 相机默认固定。只在重击或终结动作使用克制的短推近，提供减弱动态效果；普通攻击不反复摇晃整个界面。

## 战斗节拍

单次动作的示意：攻击牌抬升 → 攻击或施法 → 命中瞬间短停顿 → 伤害数字和血条变化 → 归位。普通攻击宜短、技能更完整、终结稍有停留。具体时间由原型实测决定，不把建议毫秒值当成已验证参数。

当前实现有 `PLAYBACK_STEP_MS = 1150` 的回放步长，卡片位移与命中特效各有时长。应先核对并统一它们的时钟，尤其是暂停、倍速、实时事件排队、减弱动态和最终结果的衔接。扣血展示需与权威事件一致，不因动画改变结算。

## 3D 路线选择

| 路线 | 带来的变化 | 取舍 |
| --- | --- | --- |
| 2.5D 牌桌与实体卡（推荐首版） | 共享透视、厚度、接触阴影、抬升和定向攻击；继续利用现有卡面和特效 | 需要统一 DOM 卡牌与画布特效的空间映射，但资产改造较少 |
| 完整 3D 场景与卡牌 | 更自然的场景光照、遮挡与相机运动 | 需重做拾取、投影、文本叠层、性能和不同设备适配 |
| 角色模型出卡战斗 | 英雄离开卡面成为模型参与战斗 | 需要持续制作模型、骨骼、动画与技能资产；适合后续独立范围评估 |

## 启发式检查

0–4 分，仅对本次可检查部分给初步分数。未验证项不记零分，也不虚构总分。

| 启发式 | 分数 | 依据 |
| --- | --- | --- |
| 系统状态可见性 | 2 | 回合、血量和当前技能存在，但主次不清 |
| 符合用户语言与现实映射 | 2 | 卡牌和阵型可理解，A2/B1 等标签与背景空间仍需转换 |
| 用户控制 | 3 | 代码有播放、暂停和重播；逐步与倍速可增强 |
| 一致性 | 3 | 美术统一，但展示卡与战斗卡信息密度不同 |
| 错误预防 | 未评 | 本次未操作部署和结算流程 |
| 识别优于记忆 | 2 | 敌方相似卡背和位置编号提高识别成本 |
| 使用效率 | 2 | 行动顺序可见，战报分散，当前回放控制仍可增强 |
| 简洁与视觉层级 | 1 | 多重框线、重复信息和空槽占据大量空间 |
| 错误恢复 | 未评 | 本次未测试连接中断等状态 |
| 帮助与说明 | 1 | 截图中主要靠缩写和微小文本说明战斗 |
| 已评部分 | 16/32 | 展示层需明显改进；不是完整产品评分 |

认知负荷检查：单一焦点、信息分块、视觉层级、渐进披露四项不足；相关内容分组基本成立；单步任务和选择数量不构成当前主要问题；记忆负担仍需实际观战验证。已发现 4 项，属于应优先处理的高负荷。

用户视角：首次观战者难以从 A2 → B1 和相似敌方卡背理解攻击关系；策略玩家要在战场、行动顺序、日志之间反复对应；低视力玩家会受到微小文字和低对比次要标签的影响。建议同时提供放大查看、键盘聚焦及减少动态的路径。

## 实施顺序与验收

1. /arrange、/distill：先扩大战场、压缩两侧、合并日志。
2. /animate：以一个近战、一个远程、一个治疗事件验证共享空间与统一节奏，再覆盖状态和死亡事件。
3. /typeset、/clarify：整理卡面与行动顺序，确保单位身份、命中对象和后果无需读日志也能看懂。
4. /polish：统一材质、阴影、留白和窄屏显示。

验收：普通攻击、技能、治疗、未命中、死亡、暂停/恢复、重播、减弱动态和实时事件连续抵达均保持状态准确；投射物命中视觉位置；卡牌文字可读；胜利/失败使用原有表现，仅在最后一次动作收束后触发。
