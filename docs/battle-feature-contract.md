# 战斗规则与缺口策划

更新：2026-10-13。本文是当前规则和下一步实现的具体约定；“已实现”和“已策划”必须分开。

## 保留的方向

- BP来自图片角色背景，竞技只匹配相近BP；不把所有角色改成同一战力。
- Train允许自己的卡互相对战，不收竞技押注、不产生竞技死亡，不新增付费试错入口。
- 本阶段优先修正确性、落实规则和明确内容设计；真实充值不在本轮范围内。

## 已实现的基础战斗

| 特征 | 规则 | 验收场景 |
| --- | --- | --- |
| 多目标技能 | 玩家选择一个合法主目标，再按距离、剩余HP优先选择其他合法存活目标；最多命中TARGET_NUM人；不越过技能范围；蓝耗只支付一次 | TARGET_NUM=2选择B2，先结算B2再结算B1，各产生事件，合计蓝耗仍为一次 |
| 友方技能 | Ally包含施法者；Self只包含本人；DMG=0的友方技能不造成友军伤害 | 两个受伤队员含施法者各恢复25HP，施法者只扣一次MP |
| 开场被动 | 准备完成后自动触发一次；不占行动、不扣MP；不进入主动技能按钮；持续效果遵守BUFF_TIME | 准备阶段不触发；双方确认后触发；下一次主动行动不会重复触发 |
| 增益与减益 | 每个BUFF字段分别保留；pray增加对应属性，curse降低对应属性；不能取第一个非零值套到全部属性 | 攻击+12、防御+8分别生效，未标记的速度不变化 |
| 冰冻 | BUFF_EV降低闪避并以每点5速度减速；BUFF_AC降低命中；不自动增加未指定效果 | 只配置闪避字段时，命中保持不变 |
| 中毒/流血/燃烧 | 下一回合开始造成持续伤害；优先用BUFF_HP，兼容旧卡BUFF_DMG；不能变成对敌方的治疗 | 中毒25不在命中时恢复敌人HP，下个回合扣25 |
| 持续治疗/回蓝 | 下一回合开始结算，受最大HP/MP限制；倒地者不能被持续治疗复活 | 治疗与回蓝同时配置时，两者都生效 |
| 眩晕 | BUFF_TIME表示需要跳过的行动次数；回合切换不消耗次数，实际跳过行动后减少 | 对方本回合已行动，随后受到1次眩晕，下回合仍要跳过行动 |
| 等待 | 本人恢复最大HP与MP的10%，不超过上限；眩晕中不能借等待恢复 | 人类主动等待恢复资源；自动控制器不主动选等待 |
| 回放 | 一个目标结算对应一个事件和一张战场快照；初始状态独立保存 | 双目标技能回放中能够逐个看见目标扣血，而非到回合末一起跳变 |

无`effects`的旧状态保留原有标量解释；新技能使用独立的结构化字段。开场被动的旧敌方技能可触发一次开场攻击，但新生成被动限定为自我或友方的增益。

新生成状态的持续时间限定为1–3回合/跳过行动；旧卡不批量重写。治疗状态也可以附带独立属性增益；持续伤害状态的BUFF_DMG代表伤害量，不同时作为攻击降低量。

技能文案的身份设定可以自由创作；可执行效果必须来自字段。生成器和界面不能承诺下面仍未实现的功能。

## 遗物与附魔：已策划，尚未接入战斗

当前装备、绑定、洗除和材料流水可用，但保存描述不会自动改变战斗属性。界面需要明确说明这一状态。

下一步使用版本化的`battle_effects`结构，不能让战斗引擎解析自然语言`effect_profile`。每条效果包含：`version`、`trigger`、`stat`、`operation`、`amount`、`duration_rounds`、`target`。触发只允许`battle_start`或`round_start`。

- 装备槽：每卡一件遗物；进入战斗时拍摄装备快照；换装只影响后续对战。
- 附魔槽：每卡一次绑定机会；洗除后原材料不返还、机会不重置；按现有生命周期继续。
- 一期效果：碎片提供一种增益；遗物按家族提供一种主效果。先实现静态或开场效果，不引入脚本技能。
- 数值预算草案：碎片总增益不超过该卡原始属性预算2%；装备遗物不超过3%；同卡合计不超过5%。稀有度先增加外观与收藏价值，不扩大此上限。
- 固定预算需使用现有STAT_COSTS计算；百分比不得直接叠加在已加成的属性上；DEF/PI最高80，CC/EV/AC/CA最高100。
- BP匹配保持当前标称BP方式；启用效果前，用同BP、不同装备的模拟对战验证预算，公布效果及其上限。

| 家族（覆盖当前目录） | 一期效果草案 | 触发/边界 |
| --- | --- | --- |
| Fire | 提高攻击 | 开场加成，受预算上限限制 |
| Frost | 提高防御 | 开场加成，不额外制造冰冻技能 |
| Light | 提高最大MP | 开场，当前MP同步增加相同值 |
| Void | 提高穿透 | 开场，最高80 |
| Storm | 提高速度 | 开场，不增加行动次数 |
| Beast | 提高最大HP | 开场，当前HP同步增加相同值 |
| Water | 提高最大MP | 开场，当前MP同步增加相同值 |
| Stone | 提高防御 | 开场，最高80 |
| Memory | 小额回蓝 | 回合开始，整场总恢复量受预算上限限制 |
| Blood | 提高暴击伤害 | 开场，最高100 |
| Death | 提高最大HP | 开场，不包含复活 |
| Nature | 小额回血 | 回合开始，不能复活；整场总恢复量受预算上限限制 |

| Steel | 提高命中 | 开场，最高100 |
| Celestial | 提高最大HP | 开场，收藏稀有度不额外扩大预算 |

验收必须覆盖：未装备时不变；装备/附魔后可在Train验证；洗除或卸下后恢复；旧回放不变；重复绑定不重复叠加；任意已上架物品都有明确效果；客户端不能自行决定正式战斗加成。

## PvE第一期：虚空迷宫，已有可玩原型

完整目标：[一期策划](pve-void-labyrinth-v1.md)。准确实现范围、接口和验证：[原型状态](pve-void-labyrinth-prototype.md)。docs/data保留策划草案；运行时使用backend/data/void-labyrinth-v1.json。

已实现：团队原始BP之和对应1000/5000/10000三档固定预算；每档10份遭遇配置（路线8战、2营地），两处分支；1–4友军、最多6敌人；PvE同列前后排、固定NPC脚本与意图栏、1/2/4目标Boss仪式、拆锚/控制取消/一次扣蓝；跨战资源、每人每场两次等待、营地35%恢复或2%预算进攻增益、检查点与免费重试；PostgreSQL完整行动/RNG存档、revision/幂等请求与唯一首通账本。不改变竞技匹配、竞技生命或Train成本。

验收已覆盖：三档强力测试队完整路线；六活跃敌人都有行动；全近战可击破前排后拆锚；释放目标锁定且倒地不补人；Boss诅咒影响下一完整回合（按引擎开始回合移除规则换算为两个计时ticks）；拆锚影响当前预告；眩晕/MP不足取消；第30回合有敌人存活不能通关；等待用尽不恢复；营地与重试不累计增益；状态/RNG恢复；服务端归属核验；重复请求/首通只结算一次。

原型限制：普通攻击按识别的物理TYPE分类，未知类型保留开放范围；正式NPC肖像/环境、卡牌上的预告标记、音频、美术精修、Dust及正式外观奖励、最佳纪录汇总、友军自动托管、离线PvE与跨版本迁移仍待实现。mock只可预览编队；真实冒险需要live后端。真实BP阵容平衡与真人完整通关未标定。遗物战斗加成、护盾/净化/召唤/冷却/护卫不作为本期通关依赖。

## 群体技能表现与六敌人接口：已实现

- 一次施法的所有目标事件共享 `actionId`，带 `targetIndex`（从0开始）和 `targetCount`（本次实际合法目标数）。主目标先结算，MP仅在第一个事件记录；每目标仍有独立的暴击、闪避、状态、数值和战场快照。
- 回放以施法为节拍：施法者只行动一次。多数群体法术复用现有instant粒子与命中特效；直射技能从同一来源向各目标发射，近战只攻击主目标一次并在所有受影响卡牌上播放命中特效。每个目标独立反馈；全部命中后才允许下一行动或结果揭示。轮询不会重启本次动画或延长既有停顿。
- 不完整的实时施法事件先缓冲。没有 `actionId` 的旧回放仍逐事件播放，不能按同名技能推测合并。减少动态效果时保留目标数、静态结果数字和已结算战场。
- 新模式 `pve_4v6`：A侧1–4名玩家角色，B侧1–6名敌人，两侧均保留6个站位；超员或空队报错，不截断名单。自动团队结算、REST会话及准备/确认流程支持该模式。敌方在手动单人会话由程序驱动，六个敌人均进入行动序列。
- 接口：`POST /api/battle/team` 使用 `size: "pve_4v6"`；`POST /api/battle/sessions` 使用 `battleMode: "pve_4v6"`。前端 `prepareBattleSession` 第五参数可指定该模式；默认竞技模式保持原样。此通用接口提供遭遇战基础；虚空迷宫已有独立持久化run接口，不通过通用试验会话推进冒险或领取奖励。
- 现有VFX测试模式增加 Duel / Full 6 vs 6 / PvE 4 vs 6，以及1/3/6目标。Heal和Pray选友方，负面状态选敌方；不足目标时显示实际数量。保留拖动站位、暴击、伤害量及Replay，使用正式战场渲染器与事件结构。

验收覆盖：六敌群攻命中B6、主目标优先、一次扣蓝、六个独立快照；第六敌人自动行动；四人群疗不能产生第五个友方；六目标远程与近战/状态落点；旧回放兼容；实时事件分批到达；人数超限返回400。


## 当前多目标表现：复用现有instant系统

群体法术在同一施法节拍直接在各目标位置播放仓库既有instant效果。火用fire、冰用frost、雷用thunder、圣光/治疗用light配合原状态色；保留持续状态的边框表现和独立数值。类型转换只产生用于表现的事件副本，不修改原始结算事件、目标、MP或战场历史。当前Delivery为Auto / Instant / Direct，旧sky设置转为instant。

## 3D天降原型：已暂停，当前战场不加载

以下为暂停原型的记录，当前不继续开发、不接入新的生成素材；其运行入口与测试模式选项已关闭。

- 默认规则：实际目标超过1名的法术、元素攻击、箭雨和群体治疗使用天降；横扫/爪击/穿刺/钝击/枪械连射保留直射。单目标默认保留原表现。显式 `VFX_PRESENTATION: "sky" | "direct" | "auto"` 可以覆盖该选择，事件字段为 `vfxPresentation`；非法值归为auto。表现选择不影响命中、伤害、目标、状态或MP。
- 三维实现：独立按需加载的Three.js透明渲染层，透视相机、真实XYZ坐标、立体网格、深度测试和材质shader。目标站位屏幕坐标通过相机射线映射到水平三维地面，随拖动、窗口尺寸和战场视角重新登记。卡牌/场景DOM保留；没有把整个UI改为三维场景。
- 施法者原地施法，落点先出现环形预兆；火/岩石用陨石、冰用冰锥、雷用雷柱、治疗/圣光用光柱，其余用对应色的能量棱体，箭用箭雨。火焰通过噪声shader变化，落地有碎屑、粒子、半球扩散和水平冲击环。目前是程序化基础模型/材质；精细角色/法术美术资源尚未制作。
- 节奏：260ms预兆，460ms下降，目标间错开28ms、最多140ms，540ms冲击消散。每目标在自己的下降结束时通知命中；回放仍等最后目标反馈后再进入后续节拍，不重复扣蓝或重复结算。
- GPU边界：限制像素比例至1.5；每目标36粒子和7块碎屑；滚出视野或页面隐藏时暂停渲染。更换施法或退出时释放纹理、几何、材质与渲染上下文，消散结束后停止帧循环；减少动态效果不启动三维层。三维模块加载失败、WebGL初始化失败或上下文丢失时保留原直射层作为回退。
- 测试模式的Delivery选择可以比较自动、Skyfall 3D与Direct。验收已有天降策略、几何类型、时序、地面投影及窗口/站位变化测试；桌面浏览器做画面检查。中端移动设备性能、正式美术和声音需要另行打磨，不能把基础层视为所有技能的最终资产完成。


## VFX自定义测试小队：已实现

面板顶部可分别增加/减少友方与敌方测试卡牌，每侧1–6张，保留单挑、六对六、PvE四对六预设。调整数量进入Custom场景；技能目标可选择1–6中的任意整数，界面显示请求数与实际受影响数量。群疗依据友方人数，攻击/负面状态依据敌方人数，不足时只命中现有目标。增减只修改测试场景，不创建或删除玩家收藏卡。

已拖动卡牌优先保留站位，新卡使用剩余空位；减少人数不会让留下的卡牌移位。改变人数、目标数或效果后重新预览；Reset formation把当前人数的卡牌恢复默认站位。继续使用现有instant系统，天降仍暂停。
