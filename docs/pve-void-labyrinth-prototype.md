# 虚空迷宫：首个可玩原型

更新：2026-10-13。策划见[一期完整方案](pve-void-labyrinth-v1.md)。这是玩法与持久化原型；已加入[场景与敌人美术](void-labyrinth-art-direction.md)，完整美术包、难度标定和经济奖励尚未完成。

## 现在可以做什么

- 在客户端 **Chronicle → Void Labyrinth** 选择1000、5000、10000三个固定档位，用收藏中1–4名角色编队，调整六格内的站位。
- 访问完整十节点：六普通战、两营地、一精英、一Boss；两处分支固定后重试不换敌人。运行时加载`backend/data/void-labyrinth-v1.json`的30份遭遇，NPC属性按固定预算确定性生成，不调用造卡模型。
- 手动指挥友军；敌方按公开脚本行动；战前可看人数、总BP、身份和站位。战斗中查看敌方下一行动及Boss锁定的角色名单。
- PvE使用同列前排保护：近战先打对应列前排，空列可打后排；远程不受该保护限制。普通攻击识别Melee/weapon/warrior/sword/claw类TYPE，技能按自身RANGE；其他普通攻击暂保留开放范围。未知图片角色类型的普通攻击分类仍需标准化。
- Boss有普攻、蓄力、释放、恢复循环；三档基本覆盖1/2/4人，拆锚降低当前仪式范围/伤害/诅咒。眩晕跳过其行动取消蓄力，MP不足取消释放，死标记不补人，群伤只扣一次MP。Boss死亡会崩解锚点，守卫仍须清除。
- HP/MP与倒地跨战携带，临时状态不带出遭遇；每人每场最多等待2次。营地修整恢复35%，最多复起一人；祷灯按2%属性预算换算ATK，作用于下场前两完整回合。
- 仅清除全部敌人且己方仍有人存活才能过关；30回合未清除失败。入口与营地设检查点，免费重试恢复检查点，重打后续遭遇。
- 每次行动将完整资源、状态、NPC阶段、Boss标记与独立RNG状态写入PostgreSQL。刷新或服务重启后按原行动继续，不靠内存会话。退出页面不判负，也没有单人行动超时。
- 首通记录使用账号+主题+档位唯一键。重复请求、双标签页和旧revision不会重复行动或重复记首通；玩家属性/队伍BP从本人收藏读取，敌人和清场由服务端决定。

## 原型范围与尚未完成的内容

- 真实冒险需要 **live模式、已配置的后端与PostgreSQL、正式登录**。mock模式仅预览档位与编队，不驱动本地战斗，也不伪造云端存档。
- 战斗继续使用已有ArenaBattleScene与instant VFX。新增九种生成怪物肖像、图鉴与环境插画；入口用真实Three.js门户、石柱、台阶、灯光与镜头，怪物幻象为绘画贴图。玩家界面统一英文。六类完整房间、三档侵蚀层、主题音频与卡牌上的仪式标记仍待完成。目前标记在意图栏按角色列出。
- 原型只写首通账本与每次冒险成绩，**不发放未校准Dust，也不授予尚未制作的卡背/印记**。一期100/250/500 Dust仍是待验证的策划值；尚无个人最佳汇总、分享图或公开排行。
- 整体三档难度与正常BP阵容通关率尚未标定；强力测试队通关仅验证流程。1800条平衡模拟和真人试玩仍待执行。
- 友军自动托管和离线PvE模拟尚未开放。手动/REST统一调用同一个服务端会话与命中、状态、费用结算；现有竞技/Train规则保持兼容，独立PvE规则没有静默扩展到它们。
- 当前运行时内容版本为`void-labyrinth-v1-prototype-1`；发布后续内容时需保留活跃存档所需的旧版本。原型当前只安装这一个版本，跨版本内容迁移尚未实现。
- 历史`/api/pve/start`仍为旧tower接口及原费用逻辑，新迷宫只通过下述接口启动。不要使用旧接口创建虚空迷宫。

## 启动与操作

按[后端README](../backend/README.md)配置数据库与登录服务并启动后端。前端使用`VITE_APP_MODE=live`，`VITE_BACKEND_URL`指向该后端，运行`npm run dev`。登录后打开Chronicle；保存的活跃冒险自动恢复。完成或结束后可以另选档位/阵容。

数据库初始化新增`pve_first_clears`表，复用`pve_runs.run_payload`存储完整状态；无需修改收藏卡生命周期或真实钱包。

| 接口 | 用途 |
| --- | --- |
| `GET /api/pve/catalog` | 三档、地图与遭遇情报 |
| `POST /api/pve/runs` | 创建免费冒险，heroIds与slots来自己方收藏；带requestId |
| `GET /api/pve/runs/active` | 查询本账号活跃/失败待重试冒险 |
| `GET /api/pve/runs/{id}` | 恢复本人冒险与战斗快照 |
| `POST /api/pve/runs/{id}/enter` | 进入当前遭遇，必要时带branch A/B |
| `POST /api/pve/runs/{id}/action` | 人类友军动作，带actorTag与expectedEventCount |
| `POST /api/pve/runs/{id}/advance` | 结算一次敌方/眩晕行动；不能跳过普通友军行动 |
| `POST /api/pve/runs/{id}/camp` | rest/boon及可选reviveHeroId |
| `POST /api/pve/runs/{id}/retry` | 免费恢复最近检查点 |
| `POST /api/pve/runs/{id}/abandon` | 放弃当前未完成冒险 |

所有接口需要登录；所有run变更请求包含当前revision与唯一requestId。重复requestId须保持操作/正文相同；过期revision返回409并需刷新。PvE会话没有注册到旧内存battle-session管理器，战斗行动通过run接口执行。
