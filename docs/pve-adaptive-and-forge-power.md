# 统一迷宫入口与锻造战力校准

2026-10-16。本规则替代新冒险的 1000 / 5000 / 10000 三档 ±5% 入场带；不改变竞技匹配规则。

## 迷宫规则

- 一个入口，选择 1–4 张属于自己的可用卡，标称 BP 合计至少 1000，无上限档位和凑分要求。
- 服务端读取持有卡牌的属性，开局锁定 `entryPowerBp = max(标称团队BP, Σ属性×STAT_COSTS)`，因此稀有度带来的真实属性增益也计入。客户端提交的团队 BP 不参与计算。
- 普通战、分支战、精英、Boss 依次使用开局预算的 80%、85%、90%、95%、105%、115%；每个敌人的 BP 按配置权重以整数分配，合计严格等于遭遇预算。分支改变敌人组合，不改变总预算。
- 1 人采用原 threshold 组合，2 人采用 reflection 组合，3–4 人采用 heart 组合；它们是内部编队模板，玩家不再选择档位。最多 6 个敌人，保留对应的仪式、锚点、前后排和技能规则。
- 不因战损、奖励、遗物或检查点重试重新计算敌人强度。开局快照随冒险保存，后续获取的强化具有实际收益。
- 仍然是十层，保留事件、营地、商店、战后奖励与每战棋盘确认。服务端同时返回各分支的真实侦察数据，预览与实际生成共用同一函数。
- 新冒险首通 150 Dust，每账号的 adaptive 首通只发一次；提升 BP 或换阵容不会重复发放。测试模式的奖励不进入真实钱包。
- 已保存的旧三档冒险继续原预算、路线与首通规则，不重新标定卡牌或历史战斗。旧客户端传来的合法档位字段可兼容，但新建的服务端冒险统一为 adaptive。未知档位仍拒绝。

验收：999 拒绝、1000 接受；1273/4800/5640/17460 可直接进入；1–4 人的每个遭遇预算精确；六敌人不丢失；分支预告与实际一致；战前不扣资源；奖励、存取与重试不改变开局预算；旧 v2 爬塔仍可触发事件和领奖；首通账本/钱包同事务且重试不重复发奖。

## 为什么锻造会出现高 BP

旧代码已使用 `json_object`，但它只约束 JSON 格式，没有固定字段或类型。P1 要求模型推测背景并自由输出 BP；P2 被提示保留 BP，但服务端没有锁定它。后端数值生成器按 P2 的 BP 分配属性，稀有度只增加 0%/3%/6%/10% 的属性预算，不会将标称 BP 从一千放大成一万。

本次只读抽样的 6 条线上成功生成记录：P1、P2 与最终 BP 全部一致，中位数 1400，2 张超过 5000。因此这批记录的高分来源是 P1 判定；样本不足以证明所有生成普遍偏高，也不能仅凭代码断言每一张高分角色都判错。

测试模式另有独立原因：旧模拟锻造固定选 4960/5180/5420/5640 BP 的模板，属性预算也未与标称 BP 对齐。新模拟卡改用服务端同步的 1000 BP 初始模板，保留上传图片并明确说明没有 AI 判图；旧模拟卡保留。

## 新锻造约束

- P1 输出角色身份、可观察依据、识别置信度、档位与 0.8–1.2 档内系数；程序按固定锚点算 BP。模型输出任意额外 BP 不会覆盖结果。
- 锚点保留 human 100、beast 200、monster/elite 500、heroic 1000、demon 2000、legend 3000、demigod 5000、near_god 10000、god 20000。普通原创冒险者参考 elite/heroic，不能仅靠华丽构图、光效、翅膀或金色盔甲升为神。
- legend 以上要求模型报告已识别的既有角色、置信度至少 0.9、至少两个不同的识别细节。不满足的结构化结果拒绝并走既有退款流程，不静默生成高分卡。这是模型证据门槛，不等于外部资料核验，不能保证角色识别永远正确。
- P2 只分配模板、1–10 整数权重和两个合法技能，BP 与身份由 P1 的校准结果锁定；不能选择稀有度，也不能用最终数值替换 0/1 效果标记。稀有度继续由服务端抽取。
- 优先请求 `json_schema` + `strict:true`，各对象禁止额外字段。仅当网关明确返回“不支持 json_schema”的 400 错误时，兼容回退到 `json_object` 并记忆能力；两种模式都必须通过相同的服务端类型、范围和技能语义校验。鉴权、配额、网络与无效 Schema 错误不伪装成兼容回退。
- 不完整输出、拒绝输出和不合法的技能不保存卡牌；保留已有失败退款和卡牌/生成历史原子保存行为。历史保存原始 P1/P2、校准后数据和新版 prompt 标记，便于追溯。
- 不批量改旧卡、旧 BP 或已有 NFT 元数据；也没有为验证调用付费模型。提示词的实际分布改善需要后续真实生成样本验证。

结构化模式依据：[OpenAI Structured Outputs 文档](https://developers.openai.com/api/docs/guides/structured-outputs)。Schema 约束结构，业务战力边界仍由服务端规则承担。

已完成验证：133 项规则/生成/兼容测试、72 项隔离 PostgreSQL API 集成测试通过；完整自适应路线与首通重复请求使用测试队伍和模型桩，不代表付费模型的真实识别率或所有阵容的平衡性。真实网页已验证 5640 BP 单卡直接创建自适应冒险。
