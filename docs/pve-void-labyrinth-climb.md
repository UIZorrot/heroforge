# Void Labyrinth：十层爬塔规则

实现版本：`void-labyrinth-v2-climb-1`。保留 Chronicle 导航名、Void Labyrinth 主题、三个深度的名字、原有怪物卡图和即时 VFX。

## 入口与初始英雄

- 出战人数为 1–4，不要求四人。只选英雄，不在入口指定阵型。
- 三档团队目标 BP 保留 1000 / 5000 / 10000；服务端依据玩家拥有的实际卡牌计算总分，准入范围分别为 **950–1050、4750–5250、9500–10500**，边界包含在内。客户端显示差额，超出范围不能进入。玩家传来的总 BP 无效。
- 八名初始英雄统一为 1000 BP / common。HP、MP、ATK、DEF、CC、SPEED、CA、PI、EV、AC 的实际预算按生成器的 `STAT_COSTS` 精确合计为 1000；技能伤害、耗蓝、治疗和增减益数值同步按原角色比例缩放。
- 一名初始英雄可以进入第一档。最多四名初始英雄只有 4000 BP，不能进入 5000 或 10000 档；更高深度需要锻造适合的英雄，不能用本局增益绕过入口门槛。
- 现有账号的 `starter_deck_v1` 卡牌在登录或读取收藏时按 `starter_index` 一次性迁移，保持 ID、图片、收藏装备、卡牌状态和死亡记录；玩家锻造的卡牌不受影响。旧战斗和冒险的已保存角色快照不重算。测试模式按固定 starter ID 更新人物，保留玩家自己锻造的测试卡。

## 十层路线

| 层 | 原有地点 | 内容 |
| --- | --- | --- |
| 1 | Gate of Lost Names | 战斗、12 Lumens、选一个奖励 |
| 2 | Mirror Fork | A/B 分支战斗、12 Lumens、选一个奖励 |
| 3 | Forgotten Tablets | 非战斗事件：读碑文，或以血换增益 |
| 4 | Lantern Rest | 营地：恢复/复活一人，或下场短期攻击增益；保存检查点 |
| 5 | Twin Archive | 战斗、12 Lumens、选一个奖励 |
| 6 | Broken Causeway | A/B 分支战斗、12 Lumens、选一个奖励 |
| 7 | Lost Chamber | 非战斗交易：用本局 Lumens 选购一次，或离开 |
| 8 | Oathbound Gate | 精英战斗、24 Lumens、选一个奖励 |
| 9 | Silent Refuge | 营地、保存检查点 |
| 10 | Rift Core | 首领战斗、40 Lumens、通关结算 |

每档敌人的 BP、阵容和首领仪式仍然固定，最多六个敌人。三档挑战使用相同主题和路线；敌人不随本局增益动态提高属性。

## 每场棋盘准备

进入战斗房间后，服务端先建立 `preparing` 棋盘，显示实际敌人和保留的 HP/MP，不开始行动、不扣 MP。玩家在棋盘上拖动或点选移动己方卡牌，确认完整、唯一的六格位置映射后开始第一回合。前排保护同列后排；所有英雄的位置在下一场继承为可再次调整的默认值。

`POST /api/pve/runs/:id/confirm` 接受 `positions`（标签到 0–5 格的映射）、`revision`、`requestId`。遗漏、重复、越界位置由服务端拒绝。开始后阵型锁定。GUI、REST 和本地测试均使用同一个 Python 结算器；随机状态和准备棋盘均可持久恢复。

## 本局奖励与事件

每个非最终战斗获胜后，必须从三项中选一项才能升至下一房间：

- **Ember Edge**：此局每层叠加基础 ATK 的 5%，按原基础数值加法叠加。
- **Stone Memory**：此局每层叠加基础最大 HP 的 8%；存活英雄的当前 HP 增加同样额度，倒地英雄不复活。
- **Lantern Draught**：存活英雄立刻恢复最大 HP/MP 的 25%，不超过各自上限，不复活。

增益进入下一场的实际角色数值，不只是界面标签。它们不改变入场时的团队 BP、收藏卡牌、竞技匹配或其他玩法。

第三层事件：读碑文得到 20 Lumens 并恢复存活英雄最大 MP 的 15%；血铭消耗存活英雄最大 HP 的 10%（至少留下 1 HP），得到一层 Ember Edge。

第七层交易：Ember Edge 45、Stone Memory 40、Lantern Draught 30 Lumens；任选一次购买，或免费离开。资金不足不能购买；选择后升层，不能重复领取或消费。Lumens 是本局货币，不兑换账号 Dust，不结转下次冒险。

营地保留原本恢复/复活规则与 Lantern vow 的两回合增益。倒地只影响本次冒险，免费检查点重试不产生卡牌死亡费用。

## 持久与永久奖励

通关第一档、第二档、第三档的首次完成分别奖励 **75 / 150 / 250 Dust**，每账号每深度一次。首通唯一记录、钱包增加、资源流水、冒险完成状态在同一个数据库事务中提交。重复请求、重复通关、刷新或并发重试不得再次增加钱包。

检查点保存资源、阵型、本局增益、Lumens、选择历史和未领选择。重试整体回滚到检查点，保留已选战斗分支、增加重试次数；不会累积检查点之后重复获取的奖励。不同层消耗 MP 的次数与数值仍由统一战斗引擎决定。

旧 `void-labyrinth-v1-prototype-1` 冒险保留八战斗的原路线、原有入场快照，允许继续或结束；新开冒险必须符合 ±5%。旧首通记录继续占用同深度的唯一首通资格，不追溯补发 Dust。

## 本地测试客户端

仅 Vite 开发构建 + mock 模式可以调用本地爬塔测试服务。运行 `backend/.venv/Scripts/python.exe backend/pve_preview.py`，监听 `127.0.0.1:5545`；前端开发代理将 `/api/pve-preview` 转发给此服务。它拒绝外部来源，使用实际 Python 战斗规则，并将测试存档保存到忽略目录 `_local/void-labyrinth-preview.json`。生产 Flask 应用不注册该入口。

测试奖励只记录测试首通和 preview Dust，不连接账号数据库、不修改真实钱包。发行版 mock 仍只预览；真实冒险必须登录正式服务。

## 验收场景

1. 950/1050 BP 单人允许进入，949/1051 拒绝；人数 0、5 或重复英雄拒绝。第二、第三档同样按 ±5% 检查。
2. 八名新/旧初始英雄的实际预算为 1000，所有主动技能有可支付的耗蓝；锻造卡和收藏装备保持原记录。
3. 每个战斗节点先准备；移动、刷新不会消耗资源；确认前提交行动失败，确认后用实际位置结算。
4. 击败普通怪后出现三选一，未选不能升层；选择攻击/最大 HP 能改变下一场实际数值；恢复不超过上限且不复活。
5. 第三、七层无需打怪；事件资源变化正确，交易支出一次；资金不足不改变状态。
6. 全十层可完成，包含六战斗、两营地、事件和交易。死亡、30 回合失败和免费重试仍然有效。
7. 检查点重试回滚增益、货币和选择；分支固定；持久 RNG、己方耗蓝和每目标事件维持一致。
8. 首通钱包增加一次，重复网络请求及第二次通关不增加；失败事务不能留下已领取标记。
9. 桌面英雄阵列分行，无原有横向截断；小屏两列英雄、单列奖励；战场和选择内容保持可达。

当前改动为可玩的规则实现。长期平衡、更多事件/路线、独立奖励物品美术、音效和完整真人移动端体验仍需后续打磨。
